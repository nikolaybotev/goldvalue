# Review instructions

## Passes

Run three passes and tag each finding with its pass:

- **Bugs:** logic errors in date parsing, period resolution (PM/AM fallback, roll-back, averaging, YTD), unit arithmetic (`GB_PER_OZ = 1000`, `GBD_PER_OZ = 50`), CSV round-tripping.
- **Security:** unsafe file handling in cache/batch paths, unpinned or unnecessary network calls, secrets or personal data in the repo, dependency additions to the standard-library-only Python script.
- **Compliance:** the change matches `intent/<change>/spec.md` and `plan.md`, honours the conventions in `AGENTS.md` (USD-routing tenet, benchmark-not-retail pricing, methodology disclosure), and keeps the Python reference and any TypeScript port in parity (golden vectors updated together).

## What Important means here

Reserve Important for findings that would produce a wrong gold value, present a gold-denominated figure as CPI-adjusted, break the CSV contract shared with `--batch`, violate a data source's terms, or diverge from the committed plan without updating it. Style and naming are nits.

## Cap the nits

Report at most five nits per review; summarize the rest as a count.

## Do not report

Generated data under `apps/web/public/data/`, `test-vectors/*.json` regenerated by CI, formatting that Biome/CI already enforces, and wording inside the verbatim prompt block of any `intent.md`.

## Writing

Check each pull request for:

- **No self-references:** In prose about this repo, say "this repo". Distribution entry points (a curl|sh one-liner, an installer's default source, or a dependency on another repo) may hardcode the canonical location; add an optional override for forks where that is cheap. Do not make install instructions depend on an env var the reader must set. Never derive this repo's identity from `GITHUB_REPOSITORY` in code that other repos' CI may run; in this repo's own workflows, `${{ github.repository }}` and `${{ github.repository_owner }}` are fine. References to other repos are fine. Keep the copyright name in `LICENSE`.
- **No values of variable config:** do not copy the current value of a setting into docs, tests, or workflows; name the env var, secret, or config key. Tests assert behavior against the configured value, not a literal. Product definitions are not settings.
- **Don't state the obvious (human-facing docs only):** in README, user docs, and setup docs, drop notes a competent reader already knows (for example "(healthy: exit 0)"). Agent-facing files (`AGENTS.md`, `REVIEW.md`, skills, and intents written for agents) keep explicit expectations; do not strip those notes there.
