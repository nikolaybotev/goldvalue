## Phase 1a — Reference CLI changes (spec §5.6 items 1–3 and test hooks)

Files: `.agents/skills/gold-value-normalizer/scripts/goldvalue.py`, `tests/python/{conftest.py,test_*.py}`, `SKILL.md`, `reference.md`.

1. `--batch` emits the FR15 schema (`date, amount, currency, label…passthrough, effective, gold_usd_per_oz, troy_oz, GB, GBD, USD, price_source, granularity, note, fx_rate, fx_effective, fx_mode, fx_note`); `amount` echoes the input token; LF line endings; computed export columns are ignored on input and an imported `currency` column is dropped and regenerated.
2. `--json` and text output expose top-level `effective`, `granularity`, `note`, `points` (keep old keys as aliases where SKILL.md/reference.md document them).
3. Behavior fixes: `--batch` rejects future dates like single-query mode; month queries for the current month say "(month to date)"; `parse_amount` rejects non-finite values (`nan`, `inf`) and exponent forms are kept only if intentional (decide and document).
4. Test hooks: `GOLDVALUE_TODAY=YYYY-MM-DD` overrides "today"; `GOLDVALUE_OFFLINE=1` (or `--no-refresh`) prevents network and stale-refresh.
5. pytest scaffolding: `conftest.py` loads the script via `importlib.util.spec_from_file_location`; `tmp_path` sets `GOLD_PRICE_CACHE_DIR`; `_download` is monkeypatched; network tests are `@pytest.mark.network` and excluded by default.
6. Tests: parsing (every FR2 form, lenient `strptime` cases), resolution branches, batch schema/round-trip, hooks.

DoD: `pytest tests/python -q` green on 3.9 and 3.12. `AGENTS.md`: pytest command, env hooks, batch schema.

Build notes (Phase 1a) — decisions and deviations:

- **Month/year-to-date is decided by `today`, not by the last cached fix.** The old rule (`year >= last_daily.year`) mislabelled a finished year as "year to date" on 1 January. Now `(year, month) == today's` gives "(month to date)" and `year == today.year` gives "(year to date)". `today` is `GOLDVALUE_TODAY` or the local date. Consequence for Phase 1b/2: golden vectors carry an `input.today` field (an addition to spec §5.7's `input`), and `convert` in `core` takes `today` as a parameter.
- **Roll-back boundary note.** A day in the LBMA era with no fix within 9 days (e.g. 1968-03-24 during the London closure) used to fall back to the monthly value with the note "no daily data before 1968", which is wrong. The note is now "no LBMA fix within 9 days before D; used the monthly price". Pre-1968 days keep the old note. The spec is silent on this note text.
- **`usd` header ambiguity (FR14).** `USD` is both an amount alias and a computed export column. It is ignored as computed only when the header also has `troy_oz` or `gold_usd_per_oz`; otherwise it remains an amount alias, so pre-existing `date,usd` inputs keep working. All other computed columns and `currency` are always ignored.
- **`currency` column with `--from`**: `--batch --from GB` writes `GB` (the unit the amount is in) in `currency`; `USD` otherwise.
- **Number formatting.** `--batch` now writes fixed-point numbers (price 4, oz 6, GB 3, GBD 4, USD 2 decimals) instead of Python `round()` reprs, so output never contains exponents and is byte-portable to TypeScript. `--json` `gold_usd_per_oz` is now unrounded (was rounded to 4 decimals) so vectors and the port compare at 1e-9. Old `--json` keys (`input.period`, `input.granularity`, `price_note`, `price_points`) stay as aliases.
- **`fx_*` keys** are present in `--json` and `--batch` now (`null` / empty) so the schema does not change in Phase 6a.
- **Amount grammar.** Exponent forms, `nan`, `inf`, and overflowing values are rejected (FR3 lists only plain decimals). Non-ASCII date input is rejected, and year `0000` is rejected, so the TypeScript parser has a well-defined domain.
- **`--no-refresh`** added alongside `GOLDVALUE_OFFLINE`. Offline with a missing cache file is an error; `--refresh` in offline mode is an error.
- Negative amounts containing `,` or `$` need `--` on the command line (argparse reads `-1,500` as an option); `--batch` is unaffected.
- CI `python` job now runs pytest on 3.9 and 3.12. Locally verified on 3.9.25, 3.12.14, and 3.14.7.

## Phase 1b — Synthetic fixture, vectors, data sync

Files: `test-vectors/snapshot/*`, `test-vectors/{gold-usd.json,dates.json,batch-*.csv}`, `tools/snapshot/sync_data.py`, `.github/workflows/weekly-drift.yml`.

1. `test-vectors/make_fixture.py`: deterministic synthetic `lbma_daily.csv` (1968-01-02 → a fixed end date, London weekdays, AM/PM columns with the real gaps: AM-only Jan–Mar 1968, closure 1968-03-15 → 1968-04-01) and `monthly.csv` (1833-01 → end); also emits the same data as LBMA-shaped JSON for Playwright route stubs. Regenerating must be byte-identical.
2. `--vectors OUT.json` reads a committed case-input file (not the shipping script) and writes `json.dumps(sort_keys=True, indent=2)` output plus trailing newline, from the fixture with `GOLDVALUE_OFFLINE=1`. Schema is spec §5.7 extended with `input.currency`, `expected.fx_note`, `expected.points`. Families per §5.7; the London closure boundary is 1968-03-15 → 1968-04-01.
3. `dates.json`: accept/reject strings generated by the CLI's own parser (oracle for `dates.ts`).
4. `sync_data.py` (stdlib): runs the CLI fetch into a temp cache, copies `monthly.csv` (and later `fx_*.csv`) verbatim to `apps/web/public/data/` — never `lbma_daily.csv` — and writes `manifest.json` (`files: {name: {rows, last_date, sha256}}`, no timestamp, so unchanged data means no diff), and fails if any file's row count drops more than 1% from the previous manifest.
5. CI: regenerate vectors from the fixture and diff byte-for-byte (determinism). `weekly-drift.yml`: non-blocking comparison of live sources with the fixture.

DoD: AC7 (Python side) green; `AGENTS.md`: vectors command and the rule "change Python and TS together, regenerate vectors, commit all".

Build notes (Phase 1b) — decisions and deviations:

- **Driver.** `test-vectors/regenerate.py` regenerates everything (fixture, `gold-usd.json`, `dates.json`, `batch-*-out.csv`); CI runs it on Python 3.9 and 3.12 and fails on any `git status` difference under `test-vectors/`. Cross-version determinism found one hazard: `sum()` of floats changed in Python 3.12, so the fixture uses `math.fsum`.
- **CLI interface.** `--vectors OUT.json` needs `--cases FILE` (the committed `test-vectors/cases.json`); `--dates-oracle OUT.json` reads the `dates` list from the same file. Both force offline mode and read the tables in `GOLD_PRICE_CACHE_DIR` (the snapshot).
- **Vector schema** is spec §5.7 plus `input.today` (Phase 1a decision: MTD/YTD notes and the future-date rule depend on it), and `name` and `family` labels per vector. The `today` keyword is excluded from vectors. `expected.gold_usd_per_oz` is unrounded. `fx_*` are `null`. The file is a JSON array; `json.dumps(sort_keys=True, indent=2)` plus a newline.
- **`dates.json`** is `{"today", "accept": [{"input", "kind", "anchor"}], "reject": [...]}`, including the `today`/`now`/`latest` keywords resolved against the pinned `today`. It accepts years `0001` to `9999`, so the TypeScript port must not use `Date` constructors that remap years below 100.
- **Fixture.** `monthly.csv` is synthetic too (1833-01 to 2026-09; 20.67 through 1933, about 35 for 1934-1967, monthly means of the synthetic daily fixes from 1968), which keeps the whole snapshot pinned and licence-free. Beyond the plan's gaps, Dec 25, Dec 26 and Jan 1 are skipped on weekdays, and four days have a single fix (`PM_MISSING`: 1990-06-13, 2009-07-22; `AM_MISSING`: 2002-09-11, 2019-10-16). The generator ends 2026-09-25 (a Friday). The JSON stubs (`gold_am.json`, `gold_pm.json`) are committed (about 1.4 MB) so Playwright and vitest can load them directly.
- **Real LBMA JSON shape (observed 2026-09-29):** rows are `{"is_cms_locked": 0, "d": "YYYY-MM-DD", "v": [usd, gbp, eur]}` and `eur` is `null` before 1999. The fixture reproduces this; `lbma.ts` (Phase 2) must ignore extra keys and null entries.
- **`sync_data.py`** fetches only `monthly.csv`, by calling the CLI's `fetch_monthly` (not `--fetch-only`, which would also download LBMA). `--source-dir` and `--previous` exist for tests and the row-count guard. `apps/web/public/data/` is gitignored because Phase 5 syncs at build time.
- **`weekly-drift.yml`** runs `tools/snapshot/check_drift.py` (shape, CORS, freshness, 1968 gap structure; never values, since the fixture is synthetic) and the live `-m network` pytest with `continue-on-error`.
- `.gitattributes` adds `test-vectors/batch-*.csv -text` so the CRLF/BOM input fixture keeps its bytes.

Build notes (Phase 2) — decisions and deviations:

- **API.** `parseDate(text, today)`, `parseAmount`, `parseUnit`/`toOz`/`fromOz`, `parseDataCsv`, `GoldTable` (`fromCsv` or constructed from entries), `priceForDay/Month/Year` + `resolve`, `convert(table, amount, unit, period, today)` and `convertQuery(table, {amount, date, from, today})`, `importCsv`/`exportCsv`/`runBatch`/`batchLayout`, and `fetchLbmaSince`/`parseLbmaJson`/`mergeLbma`/`lbmaToDaily`. The result of `convert` has the CLI `--json` keys (`gold_usd_per_oz`, `troy_oz`, `GB`, ...). Errors are typed (`DateParseError`, `FutureDateError`, `AmountParseError`, `PriceNotFoundError`, ...).
- **`today` is an explicit parameter** everywhere the CLI reads the clock (keywords, future-date rule, MTD/YTD notes), matching `input.today` in the vectors.
- **Date parser.** `dates.ts` rebuilds Python's `strptime` regexes (same alternation order, `re.IGNORECASE`, `\s+` for spaces, "match a prefix then reject leftovers", the ` [1-9]` day alternative) and Python's `str.strip()` set. Verified by a differential fuzz run against `parse_period` (49,279 generated strings, 26,959 accepted, zero mismatches) plus the committed 106-string oracle. The fuzz harness is not committed. No `Date` objects: years 1 to 9999 use pure calendar arithmetic.
- **Numeric parity.** `fsum.ts` ports CPython's `math.fsum` (period means are exactly rounded like `statistics.fmean`); `formatFixed` formats doubles like Python's `f"{x:.Nf}"` with exact ties-to-even (JavaScript's `toFixed` rounds exact ties up). Both were fuzzed against Python (3,000 sums, 20,000 formatting cases, 40,000 amount strings, zero mismatches). TypeScript batch output is byte-identical to `goldvalue.py --batch` for all four `batch-*-in.csv` vectors, and each output re-imports unchanged (AC3).
- **CSV.** Papaparse only parses (delimiter fixed to `,`, `step` mode to recover physical line numbers like `csv.reader`); the writer is our own (`quoteField` = `csv.writer` QUOTE_MINIMAL) because `Papa.unparse` quotes differently (leading/trailing spaces) and would break byte parity.
- **The plan's "dedupe rule" is undefined in the spec; the project's reading, implemented in Python and TypeScript:** header names compare trimmed and case-insensitively and the first column wins; passthrough columns named like any FR15 output column are dropped (so a `USD`, `Note`, or second `amount` column never duplicates an output header). Python `run_batch` now uses `csv.reader` (not `DictReader`, which keeps the last duplicate). New vector pair `batch-dedupe-*.csv` covers it.
- **Empty daily table.** `GoldTable` with no daily rows (LBMA not loaded yet, spec 6.3) resolves LBMA-era queries from the monthly series and appends "daily LBMA prices not loaded" to the note (day: "daily LBMA prices not loaded; used the monthly price"). Python cannot be in this state, so there is no vector; it is unit-tested. Pre-1968 queries keep their usual notes.
- **`lbma.ts`** tolerates extra JSON keys and null USD/EUR entries (see Phase 1b) and rejects other malformed shapes; `fetch` is the injected minimal `FetchLike` (no DOM types).
- **TS projects.** Root `tsconfig.json` references `packages/core`, `packages/core/test` (adds Node types for fixture loading) and `apps/web`. A scan test asserts `src/` has no DOM or Node imports.

Build notes (Phase 3a) — decisions and deviations:

- **Layout of `apps/web/src`.** `lib/` (pure helpers: `format`, `clock`, `period`, `paste`), `store/` (`data.ts` boot/IndexedDB/LBMA, `sheet-store.ts` rows/settings/results signals, `compute.ts` per-row result, `rows-logic.ts` pure row operations), `sheet/` (`Sheet.tsx` view, `controller.ts` keymap and actions, `nav.ts` grid position state). Pure modules have Vitest tests (`apps/web/test`); `compute.test.ts` replays every USD golden vector through `computeRow`.
- **Core additions (backwards compatible).** `parseMonthlyCsv` is exported from `table.ts` so the app keeps the monthly entries and rebuilds `GoldTable` when LBMA data arrives; `packages/core/package.json` gets `"sideEffects": false` so the app bundle tree-shakes unused exports. The app never re-implements resolution: rows call `parseAmount`, `parseDate`, `checkNotFuture`, and `convert` directly (not `convertQuery`) so an invalid amount and an invalid date are both reported on the same row.
- **Boot.** `manifest.json` and `monthly.csv` are requested in parallel (not strictly in sequence); a missing manifest is tolerated (it only supplies the "last month" for the freshness text), a missing `monthly.csv` is the FR20 unavailable state. The stored LBMA table is read before the first table is published, so returning visitors never see a flash of monthly precision. The stored value is `{v: 1, daily: [date, usd][], fetchedAt}` (PM fix, else AM, already merged), replaced wholesale by each download because LBMA always serves the full history. A first visit downloads immediately and ignores the 12 h limit; a stale table (latest fix older than the previous London business day, weekends skipped, bank holidays not modelled) is topped up after the sheet is interactive, at most once per 12 h (`localStorage`, updated on every attempt including failures). `navigator.storage.persist()` is requested once, after the first successful save (Firefox shows a prompt for it, so it is not repeated).
- **Data status text (FR20, first cut).** A `role=status` line reads "Daily LBMA prices loaded through D", "Downloading daily LBMA prices; showing monthly values until they arrive", or "Daily LBMA prices not loaded" (with Retry). The unavailable state is an alert banner. Phase 3c adds the Refresh button and the failure detail.
- **Label column.** FR6 says the Label column is "always present"; the task brief asks for a toggle. Resolution: it is shown by default, can be hidden like GBD and Troy oz, and is always kept in storage and (Phase 4a) exports. Toggle state is persisted with the other column toggles.
- **Keymap (FR18).** Navigate mode: arrows, Home/End (Ctrl for first/last row), PageUp/PageDown, Enter or F2 edits, typing replaces the cell, Delete or Backspace clears it, Alt+Up/Down moves the row, Alt+Delete or Alt+Backspace removes it. Edit mode: Enter commits and moves down (Shift+Enter up), Tab/Shift+Tab commit and move right/left, Esc restores the value from before editing, arrows move the caret. Tab and Shift+Tab also step between cells in navigate mode and wrap to the neighbouring row; from the last cell of the last row (first cell of the first row for Shift+Tab) they are left to the browser so focus is never trapped (WCAG 2.1.2). The action buttons (move up/down, delete) are `tabindex=-1` and reachable by pointer; the keyboard equivalents are the Alt shortcuts, listed under the grid.
- **Live editing.** Following spec D8 (recompute on every keystroke) a row updates as the user types; Esc restores the previous text. Trailing-empty-row trimming happens only on commit so the row under the caret never disappears.
- **Reorder and sort.** Reorder by buttons, Alt+Arrow, and HTML5 drag from the row number (mouse only; touch users use the buttons). "Sort by date" sorts on the chart position (day itself, month 16th, year 2 July; `lib/period.ts`), alternating oldest-first and newest-first; unparsable rows follow the dated rows and empty rows stay last. Clear resets the sheet and offers Undo until the next action.
- **Paste (S2).** `parsePasted` accepts tab-separated (spreadsheet) and comma-separated text. A header row (recognised with core's `batchLayout`, so `date/period/month/year` and `amount/usd/value/price` aliases work) maps columns by name; otherwise cells fill positionally from the active cell (Amount, Date, Label). A comma table without a header is recognised only when every line's second field is a date (or the first is a date and the second an amount), so a column such as `1,500` / `2,000` is not split at the thousands separator. Single values fall through to the browser.
- **Row display.** Number columns use the CLI's `fmt_unit` precision; `data-value` carries the unrounded double for tests. The Price used cell shows the price, a source badge, and the note (visually hidden text plus a `title`); the note and price for the active row are also shown under the grid so touch and keyboard users can read them. Errors: `invalid amount`, `unrecognised date (try ...)`, `date is in the future` (FR2a); the offending cell gets `aria-invalid` and `aria-describedby`.
- **Accessibility lint.** Biome's a11y rules reject the explicit ARIA grid roles that a `<table role="grid">` needs, so `apps/web/src/sheet/Sheet.tsx` has a narrow rule override in `biome.json`.
- **Playwright.** `pnpm test:e2e` (in `apps/web`) builds and serves `vite preview` on 127.0.0.1:4173 (`exec` so the runner can stop it; `reuseExistingServer` is off so a stale `dist` is never tested). The site's `data/manifest.json` and `data/monthly.csv` are stubbed with `page.route` from `test-vectors/snapshot/`, like the LBMA JSON (`gold_am.json`, `gold_pm.json`, with the CORS header), so tests neither need `sync_data.py` nor touch a developer's `public/data`. The clock is pinned with `page.clock.setFixedTime` (Date only; timers stay real) at 2026-09-29T12:00Z, timezone UTC. Expected values come from `test-vectors/gold-usd.json` (all USD vectors dated on the pinned day, about 90 rows pasted in one go). CI `e2e` job installs Chromium with `--with-deps`.
- **Not in 3a.** Chart (3b); Method panel, refresh button, footer, layout (3c); CSV import/export (4a); service worker (4c).

Rows with the same x form a group: their circles are offset by 9 px around the group's x, the connecting line passes through the drawn positions, and hovering or tapping any member opens one tooltip listing all members (label or "Row N", requested text and plotted date, nominal USD, gold value in the axis unit, price, source, granularity).
- **Granularity wording.** "year average of N fixes" / "month average of N fixes" for LBMA-era means, "daily fix" for a day, "year average of N monthly values" for pre-1968 years, "monthly series value" otherwise. The core note stays in the sheet's Price used cell; the tooltip states granularity only, as FR12 asks.
- **Y axis (FR10, D11).** Unit buttons GB (default) / GBD / oz; "Save as default" stores `axisDefault` in settings (the button reads "Default axis" and is disabled when the current unit already is the default). The current unit is per visit and starts from the saved default. Linear by default with padded domain; negative values plot as such with a zero line when 0 is in range; the "Log scale" button is rendered only while every plotted value (and, with the overlay on, every nominal amount) is positive, and the stored preference is ignored (linear) whenever that stops being true.
- **Nominal overlay.** Off by default (persisted once toggled); drawn as a dashed grey line with square markers against a second, right-hand USD axis with its own scale (log when the main axis is log).
- **States.** Before the first valid row the chart panel shows a hint and no `<svg>` (AC2 "appears after the first valid row"); one point renders without a line and says so; the `<svg>` carries explicit `width`/`height`/`viewBox` (Phase 4b serialises it). A `ResizeObserver` on the wrapper re-lays-out the chart; height is `clamp(240, width / 2, 420)`.
- **Accessibility.** The chart is `role="img"` with a summary label ("Line chart of N rows in ..., from D1 to D2. The sheet lists the same data."); the sheet is the data-table alternative (NFR3). The tooltip is pointer-only and `aria-hidden`; there is no keyboard traversal of points in v1 (the active row's price and note appear under the sheet).
- **Synchronous update.** The chart reads the same signals as the sheet, so it re-renders in the microtask after the row changes (per keystroke, D8); the AC2 spec sets the input's value in the page and asserts the new point position one `requestAnimationFrame` later.

## Phase 4a — CSV import/export

Import per FR14 (file picker, drag-drop, 5 MB limit, per-line errors); export per FR15. DoD: AC3.

Build notes (Phase 4a) — decisions and deviations:

- **Files.** `apps/web/src/io/csv-io.ts` (pure: `importSheet`, `exportSheet`, `MAX_IMPORT_BYTES`), the actions `importFile` / `exportFile` in `sheet/controller.ts`, `lib/download.ts` (`downloadBlob`, reused by 4b), and Import CSV / Export CSV buttons in the sheet toolbar. All parsing and writing is core's `importCsv` / `exportCsv` (FR14, FR15); the app only maps rows to and from the sheet.
- **Import replaces the sheet.** The spec does not say whether import appends or replaces. Replacing is what makes AC3 (export, import, export) meaningful and matches S3 (load, adjust, export back), so the previous sheet is replaced and the notice offers Undo (the Clear undo mechanism, now `undoSnapshot`, covers both). An import that fails outright (too large, unreadable, no date/amount column) leaves the sheet untouched.
- **Limits and errors.** Files above 5 MiB (`5 * 1024 * 1024` bytes, checked on `File.size` before reading) are refused. Per-line errors (FR16) come from core with the physical line number and are listed under the toolbar (first 100 shown, then a count; the list scrolls); valid lines load. Future dates count as line errors, as in core's importer. Row count is not capped: 5 MiB is the only limit the spec sets.
- **Drag-drop** works anywhere on the page (document-level listeners that react only to `Files` drags, so the existing row-reorder drag is unaffected and a missed drop never navigates away from the app); the sheet is highlighted while a file is over the page. The file picker is a visually hidden `<input type=file>` behind the button.
- **Passthrough columns (FR14) are kept but not shown.** Rows gain `extra: string[]` and the sheet store `extraColumns`; both are persisted with the rows in the existing `goldvalue:v1:rows` entry (optional fields, so older stored sheets still load) and written back on export after `label`. Hand-typed rows pad missing values with empty cells. Clear drops the columns. A future phase can surface them in the grid; v1 has no UI for them.
- **Export contents.** Only rows with a computed value are exported, in sheet order (`date` and `amount` are echoed as typed, like the CLI's `amount` echo); rows with an error or no price are left out and counted in the notice ("N rows without a value left out"), since a CSV row without gold columns would break the shared schema. Nothing to export gives a notice, not an empty file. The file is UTF-8 without BOM, LF line endings, named `goldvalue.csv`, `text/csv`.
- **Tests.** `apps/web/test/csv-io.test.ts` runs every `test-vectors/batch-*-in.csv` through import, `computeRow`, and export and compares the bytes with the CLI's `batch-*-out.csv`, plus the export/import/export round trip (AC3 at unit level). `e2e/csv.spec.ts` covers AC3 in the browser (download -> setInputFiles -> download, byte-identical), the same batch vectors through the UI, the per-line error list (with axe), drag-drop, the 5 MB limit, the missing-columns failure, persistence of passthrough columns, and Undo.

## Phase 4b — SVG/PNG download

Serialize SVG with explicit `width`/`height`, `xmlns`, inlined styles, system fonts; PNG canvas = **exactly 2× the SVG's `width`/`height`** (independent of `devicePixelRatio`), `await img.decode()` before `drawImage`. DoD: AC4.

Build notes (Phase 4b) — decisions and deviations:

- **Files.** `apps/web/src/export/size.ts` (pure: `PNG_SCALE = 2`, `pngSize`, `sizeLabel`; Vitest), `export/chart-image.ts` (`serializeChart`, `rasterizeChart`, `downloadSvg`, `downloadPng`), and a download bar under the chart (`Download SVG`, `Download PNG`, and the size label). The bar exists only while there is a chart (same rule as the `<svg>`).
- **Serialization.** A deep clone of the on-screen `<svg>`; every element gets a `style` attribute holding the *computed* values of a fixed list of presentation properties (`fill`, `stroke*`, `opacity`, `font-*`, `text-anchor`, `color`, ...), so the file needs no stylesheet and renders the same in any viewer; `xmlns` and the explicit `width`/`height` are set (the chart already carries them). No `<style>`, `<foreignObject>`, external references, or web fonts; `font-family` is the page's system stack with `sans-serif` guaranteed at the end. The file starts with an XML declaration and ends with a newline.
- **Deliberate differences from the DOM (AC4 "equals the serialized on-screen svg").** (1) the `style` attributes; (2) `background-color:#ffffff` on the root so the standalone file is not transparent; (3) transient hover state is dropped (the `.guide` line and the `is-hover` class), because a tap on touch screens leaves the hover state behind and a guide line in a saved chart is noise. Everything else (attributes, geometry, `data-*`, `aria-label`) is identical; the Playwright test compares a canonical form (sorted attributes, `style` removed) of the parsed download with the live DOM.
- **PNG.** The canvas is set to exactly `2 x width` by `2 x height` (chart sizes are integers), filled white (a transparent PNG shows black in some viewers), scaled by 2 and drawn with `drawImage(img, 0, 0, width, height)` after `await img.decode()`. `devicePixelRatio` is never read; Playwright checks the IHDR at ratios 1 and 3 and that the image is opaque, white-cornered, and contains ink.
- **Pixel dimensions before download (FR13)** are shown as text next to the buttons ("SVG 640 x 320 px, PNG 1280 x 640 px") and follow chart resizes.
- **Filenames** `goldvalue-chart.svg` and `goldvalue-chart.png`. Errors (canvas unavailable, decode failure) show an inline alert next to the buttons.
- **Tests.** `e2e/download.spec.ts`: IHDR = 2x at DPR 1 and 3, PNG pixel statistics, SVG parses (DOMParser, no `parsererror`) and equals the DOM in canonical form, inlined styles present (series stroke colour and width, tick font family and size), no stylesheets/external URLs, the SVG loads as an `<img>` at its explicit size, hover state absent, size label correct and following a viewport resize, no buttons without a chart.

## Phase 4c — Service worker and offline

Build notes (Phase 4c) — decisions and deviations:

- **Plugin setup (`apps/web/pwa.config.ts`, used by `vite.config.ts`).** `vite-plugin-pwa` 1.3 in `generateSW` mode, `registerType: "autoUpdate"`, `injectRegister: "auto"` (a 130-byte `registerSW.js`, no `workbox-window`), `manifest: false`, `devOptions.enabled: false` (no service worker under `vite dev`; test with `vite preview`). `workbox-build` is an explicit dev dependency (peer of the plugin). `globPatterns: **/*.{js,css,html,csv,json,svg}` precaches the shell plus `data/monthly.csv` and `data/manifest.json`; `fx_*.csv` is in `globIgnores`. `navigateFallback: index.html` (denylist `/data/`), `cleanupOutdatedCaches`, `skipWaiting` and `clientsClaim`. No web app manifest or icons: installability is not in the spec.
- **autoUpdate without a forced reload.** The new worker installs, takes over immediately, and the page picks up the new shell and data on its next load; the app does not reload itself, because a reload could interrupt someone typing in the sheet. Consequence: after a daily deploy a returning visitor sees the previous data once more, then the new data.
- **LBMA is never cached (D15), three independent guards.** (1) an explicit `NetworkOnly` runtime route for `prices.lbma.org.uk` (and any `lbma.org.uk` host) is the first runtime route; (2) `globIgnores` and a `manifestTransforms` filter drop anything LBMA-shaped from the precache list; (3) no other route can match those URLs (unit-tested for every route). Playwright confirms that fetching the LBMA URL through a controlled page reaches the network every time and that no cache holds an LBMA key.
- **`fx_*.csv`** has a same-origin `StaleWhileRevalidate` route (cache `goldvalue-fx`, at most 8 entries, status 200 only). The files do not exist yet; the e2e build ships a tiny stand-in `data/fx_eur.csv` so the route is exercised (first use online, then offline).
- **"IndexedDB discarded when the manifest sha changes."** The spec does not define this; the plan only names it. Implemented as: the app derives a data version from the manifest (`lib/data-version.ts`: sorted `name:sha256` pairs, so it changes exactly when a published data file changes) and saves it with the stored LBMA table. At boot, if the stored version differs from the manifest's, the stored table is deleted and the app behaves as on a first visit (immediate download). Conservative choices: nothing is discarded while `navigator.onLine` is false (the stored table would be the only daily copy and could not be replaced, which would break NFR2), a table saved without a version or a page without a manifest never triggers a discard, and the version is stored only alongside the table. If the download after a discard fails, the app runs on monthly values with the degraded-precision note until Refresh succeeds.
- **Degraded-precision note (AC5 branch 2).** New `data-testid="degraded-note"` under the freshness status, shown while the monthly series is loaded, no daily table is in use, and no download is running: "Degraded precision: daily LBMA prices are not loaded, so every value uses the monthly gold series. Daily prices cannot be downloaded while offline; reconnect and press Refresh." Rows already carried "daily LBMA prices not loaded" in their notes.
- **E2E build and stubbing.** Service worker tests need real files behind `vite preview` (the worker precaches them, and `page.route` cannot see requests a worker answers), so `scripts/build-e2e.mjs` builds `apps/web/dist-e2e` with a synthetic `public` folder (`.e2e-public`, `GV_PUBLIC_DIR`; both gitignored) filled by `sync_data.py --source-dir test-vectors/snapshot`, and never touches a developer's `public/data`. `playwright.config.ts` now sets `serviceWorkers: "block"` for every existing spec (they stub with `page.route`); `e2e/offline.spec.ts` opts in with `serviceWorkers: "allow"` and stubs LBMA with `context.route`, which does see worker-issued requests. `setOffline` does not stop responses Playwright fulfils itself, so the spec's `goOffline` also flips the LBMA stub to fail like a dead network. IndexedDB is cleared through CDP `Storage.clearDataForOrigin` (indexeddb only; caches and the worker survive).
- **AC5 coverage (`e2e/offline.spec.ts`).** Branch 1: first visit online, rows entered, go offline, reload: shell loads from the worker, status still says daily prices loaded, GB values identical, notes say "LBMA fix on the requested date", a new row computes. Branch 2: IndexedDB cleared, offline reload: app loads, status "Daily LBMA prices not loaded; showing monthly values", degraded note visible, GB equals `amount / monthly price` within 1e-9. Also: precache contents (shell, `monthly.csv`, `manifest.json`; no `fx_*`, no LBMA) and the `fx_*.csv` runtime cache. `e2e/data-version.spec.ts` covers the sha discard (no worker).
- **Size (NFR1).** The worker adds about 8.5 kB gzipped (Workbox runtime 7.6, `sw.js` 0.9); `check-size.mjs` counts it: 74.9 kB of 250 kB. `apps/web/tsconfig.json` gains `allowImportingTsExtensions` so `vite.config.ts` can import `./pwa.config.ts` without Vite's native-config-loader warning. Lighthouse (mobile) still passes with the worker registered.
