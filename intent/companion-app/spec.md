## 1. Summary

GoldValue is a static single-page web app that re-denominates dated currency
amounts into gold units — goldbacks (GB, 1/1000 troy oz), gold-backed dollars
(GBD, 50 per troy oz), and troy ounces — and charts the result live. It shares
its data sources, cache format, and price-resolution rules with the existing
`gold-value-normalizer` agent skill, whose Python script remains the reference
implementation.

## 2. Goals and non-goals

**Goals**

- G1. Enter (amount, date) rows incrementally and see GB / GBD / oz computed instantly.
- G2. Chart the rows automatically; redraw on every edit.
- G3. Import rows from CSV; export rows (with computed columns) to CSV.
- G4. Download the chart as SVG and PNG.
- G5. Work after first load without a server (prices cached in the browser).
- G6. Deployable as plain static files on classic shared hosting, GitHub Pages, or any CDN.
- G7. Multi-currency input (EUR, GBP, CHF first) converted to gold via USD.
- G8. Numerical parity with `goldvalue.py` for every supported query.

**Non-goals**

- Reflecting local-market gold prices in non-USD currencies (explicit tenet; see §3).
- User accounts, server-side persistence, collaboration.
- CPI or other price-index adjustments (may be offered later as a comparison, not in v1).
- Dealer premiums, coin/bar product pricing, tax treatment.

## 3. Principles

- P1. **USD-normalized gold.** Any non-USD amount → USD at the historical FX
  rate for the same period → gold at the USD LBMA benchmark. Never use a local
  gold fix (e.g. LBMA GBP/EUR series) for conversion.
- P2. **Benchmark, not retail.** Use the spot benchmark (LBMA PM fix; AM where PM
  is unavailable; monthly series pre-1968). Dealer quotes such as JM Bullion are
  spot plus premium and are not used.
- P3. **Python is the reference.** Fetch, cache, and resolution logic live in
  `goldvalue.py`; the TypeScript port must pass golden test vectors generated by it.
- P4. **Static first.** No runtime backend unless a requirement cannot be met
  without one. Price data is either bundled at build time or fetched directly
  from CORS-enabled sources.
- P5. **Transparent methodology.** Every computed value can show its effective
  date, price used, source, and granularity note, exactly as the CLI does.

## 4. Users and scenarios

- S1. Compare a 2018 house price with a 2026 one in gold terms (two rows, read the numbers).
- S2. Paste a decade of annual salaries and see the gold-terms trend chart.
- S3. Load a CSV exported from a spreadsheet, adjust a few dates, export back.
- S4. Enter €250,000 in 2005-06 and see it beside $400,000 in 2024.
- S5. Open the app on a phone with no connectivity after a previous visit; existing rows still compute.

## 5. Functional requirements

### 5.1 Sheet

- FR1. Columns: `Amount`, `Currency` (default USD; hidden until multi-currency ships or when only USD is enabled), `Date`, then computed `GB`, `GBD`, `Troy oz`, and a compact `Price used` cell (price, source badge, note on hover/tap).
- FR2. Date accepts the same forms as the CLI: `YYYY`, `YYYY-MM`, `YYYY-MM-DD`, `Mon YYYY`, `today`. Invalid input marks the row, does not block others.
- FR3. Amount accepts `1500`, `$1,500`, `1,500.50`. Negative allowed (debts).
- FR4. A new empty row appears when the last row has an amount or date.
- FR5. Rows can be deleted, reordered by drag, and sorted by date.
- FR6. Optional label column (free text) that passes through to CSV and chart tooltips.
- FR7. Sheet state persists in `localStorage`; a "Clear" action resets it.
- FR8. Column toggles: show/hide GBD, oz; choose GB or GBD as the primary series.

### 5.2 Chart

- FR9. Renders as inline SVG; updates synchronously on every valid edit.
- FR10. X axis: time (rows sorted by effective date regardless of sheet order). Y axis: selected gold unit. Optional second axis or toggle for nominal USD.
- FR11. Series: line + points; single-point input renders a point; hover/tap tooltip shows label, nominal amount, gold value, price used.
- FR12. Handles mixed granularity (year, month, day) by plotting at the period midpoint and noting granularity in the tooltip.
- FR13. Download as SVG (serialized DOM with inlined styles) and PNG (rasterized via canvas at 2× device pixel ratio).

### 5.3 CSV import/export

- FR14. Import: file picker and drag-drop; header detection compatible with `goldvalue.py --batch` (`date`, `amount`, optional `currency`, `label`; case-insensitive; extra columns preserved as passthrough).
- FR15. Export: same schema as `--batch` output plus passthrough columns, so the two tools round-trip.
- FR16. Import errors are reported per line; valid lines still load.

### 5.4 Layout

- FR17. Wide (≥ 900 px): sheet left, chart right, resizable divider. Narrow: sheet top, chart below, chart collapsible.
- FR18. Keyboard-first data entry: Enter moves down, Tab moves right, arrow keys navigate.

### 5.5 Data and methodology display

- FR19. A "Method" panel states: gold-denominated (not CPI), sources, resolution rules, and links to `historical-notes.md`.
- FR20. Data freshness indicator: latest LBMA fix date in cache; manual "Refresh" button.

## 6. Data layer

### 6.1 Sources (unchanged from the skill)

| Series | Source | Coverage | CORS |
|---|---|---|---|
| Daily USD gold, AM & PM | `prices.lbma.org.uk/json/gold_{am,pm}.json` | 1968-01-02 → today | `*` (verified 2026-09-28) |
| Monthly USD gold | `raw.githubusercontent.com/datasets/gold-prices/main/data/monthly.csv` (World Bank Pink Sheet 1960+; Timothy Green/NMA 1833–1959) | 1833-01 → current month | `*` |

### 6.2 FX sources (for G7) — candidates verified 2026-09-28

| Source | Coverage | Notes |
|---|---|---|
| **BIS WS_XRU** (`stats.bis.org/api/v1/data/WS_XRU/D.{AREA}.{CCY}.A?format=csv`) | Daily, 1971+ for CHF (checked), GBP, DEM/EUR and most majors | Single source for all currencies, USD-per-unit convention, CSV. **Preferred.** |
| ECB reference rates (`data-api.ecb.europa.eu/service/data/EXR/D.USD.EUR.SP00.A`) | Daily, 1999-01-04+ | EUR only; authoritative for EUR. Cross-check. |
| FRED (`DEXUSEU`, `DEXUSUK`, `DEXSZUS`) | Daily, 1971+ | Works for active series; anti-bot layer may block automation. Fallback. |
| xe.com | — | No free historical API; scraping violates ToS. **Not used.** |

Pre-1971 (Bretton Woods fixed parities) and pre-1999 EUR (legacy currencies)
are out of scope for v1; rows in those ranges show "FX unavailable".

### 6.3 Data distribution model (decision D1, see §10)

1. **Build-time snapshot.** A scheduled GitHub Actions job runs `goldvalue.py --fetch-only` daily, converts the cache into a compact `gold.json` (date → USD price, PM-else-AM; monthly series) and `fx/{ccy}.json`, and commits/publishes them with the static site. Target ≤ 250 KB gzipped total.
2. **Runtime top-up.** On load, if the snapshot's latest date is older than the last business day, the SPA fetches LBMA JSON directly (CORS `*`) and merges newer rows only.
3. **Browser cache.** Merged tables stored in IndexedDB (via a thin wrapper); `localStorage` for sheet rows and settings. Service worker caches the app shell for offline use (G5).

### 6.4 Resolution rules

Identical to `goldvalue.py` and `.agents/skills/gold-value-normalizer/SKILL.md`:

| Query | 1968-01-02 onward | Before 1968 |
|---|---|---|
| Day | LBMA fix that day (PM else AM); else previous fix within 10 days | Monthly value |
| Month | Mean of daily fixes in month | Monthly value |
| Year | Mean of daily fixes in year (YTD for current year) | Mean of 12 monthly values |

FX resolution mirrors the same three granularities against the daily FX table
(previous business day roll-back, means for month/year). Conversion order:
`amount_ccy → USD (FX for period) → oz (USD gold price for period)`.

## 7. Architecture

```
┌───────────────────────────────┐   daily cron   ┌──────────────────────────────┐
│ GitHub Actions                │ ─────────────▶ │ Static site (GitHub Pages /  │
│  goldvalue.py --fetch-only    │  build+deploy  │ shared hosting / CDN)        │
│  build-snapshot → data/*.json │                │  index.html, app.js, data/*  │
└───────────────────────────────┘                └──────────────┬───────────────┘
                                                                │ load
                                                                ▼
                        CORS fetch (top-up only)   ┌──────────────────────────────┐
  prices.lbma.org.uk ◀──────────────────────────── │ SPA (TypeScript)             │
  stats.bis.org      ◀──────────────────────────── │  core/   port of goldvalue.py│
                                                   │  ui/     sheet + SVG chart   │
                                                   │  store/  IndexedDB + LS      │
                                                   └──────────────────────────────┘
```

- **No runtime backend in v1.** See D1–D3.
- **Packages (monorepo):** `skill/` (Python reference + agent skill), `packages/core` (TS library: parsing, resolution, conversion, CSV), `apps/web` (SPA), `tools/snapshot` (Python or TS script producing `data/*.json`), `test-vectors/` (golden JSON emitted by Python).

## 8. Technology choices

| Concern | Choice | Rationale |
|---|---|---|
| Language | TypeScript everywhere (SPA, core lib, tooling); Python stays for the reference script | Shared types between core and UI; compile-time safety on the resolution port; trivial cost with Vite |
| Build | Vite | Static output, fast, TS native |
| UI | Preact (React-compatible API, ~4 KB) + signals | Keeps bundle small for shared hosting; React can be swapped in if ecosystem needs grow |
| Chart | Hand-rolled SVG using `d3-scale`, `d3-shape`, `d3-axis` | Exact control of SVG output for clean export; no canvas dependency; small |
| CSV | `papaparse` | Robust quoting, streaming import |
| Storage | `idb-keyval` over IndexedDB; `localStorage` for small state | Simple, well-supported |
| Tests | Vitest for TS; pytest for Python; golden vectors shared | Parity guarantee (G8) |
| Lint/format | Biome | One tool, fast |
| Hosting | GitHub Pages (primary), `dist/` copy for shared hosting, optional Cloud Run static container | All static |

## 9. Non-functional requirements

- NFR1. Initial load ≤ 400 KB gzipped including snapshot data; interactive < 1 s on mid-range mobile over 4G.
- NFR2. Works fully offline after first successful load (except "today" freshness top-up).
- NFR3. Accessible: keyboard navigation, ARIA grid semantics, chart has a data table alternative (the sheet itself).
- NFR4. No third-party analytics or tracking. No cookies.
- NFR5. All numbers reproducible: for any row, `goldvalue.py <amount> <date>` gives the same GB/GBD/oz to 6 significant figures.
- NFR6. Browser support: last two versions of evergreen browsers; Safari iOS 16+.

## 10. Design decisions (answers to intent.md open questions)

**D1 — Backend: none.** Both gold sources send `Access-Control-Allow-Origin: *`,
BIS and ECB APIs are CORS-friendly, and the datasets are small. A build-time
snapshot plus runtime top-up satisfies freshness, offline, and shared-hosting
constraints with zero server code. A backend would only be justified by (a) a
source dropping CORS, (b) a paid/keyed source, or (c) server-side batch jobs.
The `core` package is designed so a thin HTTP wrapper can be added later.

**D2 — PHP vs Node: neither for v1.** If D1's fallback triggers, build **one**
implementation chosen by where it will actually run. Shared hosting → a
~100-line PHP proxy/cache is enough. Cloud Run → a Node/TS service reusing
`packages/core`. Maintaining both doubles surface area for no user benefit.

**D3 — API style if a backend appears: plain HTTP + JSON (REST-ish GET endpoints)**,
e.g. `GET /v1/price?date=1980-01-21`, `GET /v1/convert?amount=1000&date=1975&from=USD`.
GETs are cacheable by CDNs and browsers, which matters more than RPC ergonomics
here. JSON-RPC is not wrong, just uncacheable and unidiomatic on the web. tRPC
is attractive only if both ends are TS and there is real API surface; not the case.

**D4 — TypeScript: yes,** for SPA, core, and any Node tooling. The resolution
rules are exactly the kind of logic where types catch off-by-one and unit
mix-ups. Python remains the reference implementation and the skill's runtime.

**D5 — Real-time SVG chart: yes.** Data volumes are tiny (tens to low thousands
of points); SVG re-render per keystroke is cheap and gives lossless SVG export
for free. PNG export rasterizes the same SVG.

**D6 — FX source: BIS** (daily since 1971, one API for all currencies),
cross-checked against ECB for EUR. Not xe.com.

**D7 — Where computation happens: client.** Port `goldvalue.py` resolution and
conversion to `packages/core`; verify with golden vectors. The Python script
also gains a `--vectors` mode to emit them.

## 11. Open questions for review

- Q1. Preact vs React vs Svelte: any preference? (Default: Preact.)
- Q2. Should the sheet support per-row currency, or a sheet-wide currency selector? (Default: per-row column, defaulting to last used.)
- Q3. Pre-1971 FX and pre-1999 EUR legacy currencies: hard "unavailable", or a static Bretton Woods parity table?
- Q4. Chart default: GB or GBD on the primary axis? Show nominal USD as a second series by default?
- Q5. Domain/hosting: `nikolaybotev.github.io/goldvalue` first, then custom domain?
- Q6. License for the repo (MIT suggested; data sources have their own terms — LBMA data is for personal/non-commercial use, which the app must state).

## 12. Acceptance criteria (v1, USD-only)

- AC1. Entering `80000` / `2018-12` and `200000` / `today` shows 63,979.53 GB and the current-day value; both match `goldvalue.py` output.
- AC2. Chart appears after the first valid row and updates within one frame of any edit.
- AC3. Exported CSV re-imports losslessly and matches `goldvalue.py --batch` output for the same rows.
- AC4. SVG and PNG downloads open in a browser/image viewer and match the on-screen chart.
- AC5. With network disabled after first load, existing rows still compute and the app shell loads.
- AC6. The Method panel is visible and states "gold-denominated, not CPI".
- AC7. Golden-vector test suite passes in CI for both Python and TypeScript.
